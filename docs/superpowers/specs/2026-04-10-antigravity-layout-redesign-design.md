# GoNavi Website Antigravity Layout Redesign

## 1. 背景

当前官网首版已经具备完整的信息架构与数据层能力，但视觉语言仍偏“圆角卡片堆叠 + 气泡式模块化产品站”。用户明确要求后续视觉方向改为更接近 [Antigravity](https://antigravity.google/) 的布局语言，同时保留 `GoNavi` 名字、产品定位和核心文案，不照搬参考站品牌元素。

本次重构目标不是重写官网功能，而是在保留现有路由、数据层、文档与 release feed 能力的前提下，重置布局层和视觉层。

## 2. 目标与非目标

### 2.1 目标

- 将五个一级页面统一改为深色主基调
- 将全站从“模块卡片型工具站”重构为“编辑型产品官网”
- 学习 Antigravity 的布局语言：长页面节奏、强分栏、强排版、弱卡片、少圆角、弱按钮感
- 保留现有信息架构：`Home / Download / Docs / Changelog / Roadmap`
- 保留现有文案主体与产品判断，只改变呈现方式
- 保留现有 locale 路由与内容/数据层能力

### 2.2 非目标

- 不更改 GoNavi 品牌名、产品定位与核心卖点
- 不引入新的后端接口、CMS、搜索服务或部署系统
- 不新增页面类型，不改变五个一级页面的职责边界
- 不在本次重构中改写下载数据源、docs manifest、release feed 的底层逻辑

## 3. 设计结论

本次重构采用 `Editorial Product` 路线。

这意味着官网会明显学习 Antigravity 的页面节奏与布局语言，但不会把下载页、文档页、更新日志页做成纯概念展示页。所有功能页仍需保持清晰可用，只是视觉表达从“产品组件堆叠”切换到“编辑型章节叙事”。

## 4. 全站视觉原则

### 4.1 深色主基调

- 首页、下载页、文档页、更新日志页、路线图页统一使用深色背景体系
- 页面之间不再切换回浅色产品站风格
- 内容高亮区可以局部使用浅底或高对比面板，但只能作为局部强调

### 4.2 排版优先于卡片

- 视觉层级主要通过大标题、短说明、版心控制、间距和细分割线建立
- 大面积包围式卡片不再作为默认内容容器
- 标题与段落先形成阅读流，容器只用于必要的信息边界

### 4.3 减少“气泡”和胶囊感

- 大幅减少超大圆角、胶囊按钮、胶囊标签和发光浮层
- 导航、CTA、状态标签都要更克制、更硬朗
- 圆角保留，但不再是主视觉语言

### 4.4 强分栏与章节节奏

- 页面更像一篇被设计过的长文，而不是模块盒子集合
- 常用结构改为：左主右辅、左索引右正文、左标题右说明
- 页面章节之间通过留白与线性分隔建立节奏，而非反复使用边框盒子

### 4.5 品牌保留在文案，不保留旧视觉

- 继续使用 GoNavi 名称、产品定位、多数据库工作流叙事
- 放弃当前蓝绿浅底、玻璃感、柔和气泡和大量圆角卡片的既有视觉资产

## 5. 页面骨架

### 5.1 首页 `/`

首页改成真正的长页面叙事：

- 首屏使用超大标题与辅助信息列
- 向下进入连续章节，不再是整齐的卡片模块
- 内容顺序保留现有信息结构，但表达改为编辑式章节：
  - 品牌判断
  - 多数据库工作流价值
  - 产品状态片段
  - 能力版图
  - 下载 / 文档 / 社区分流

首页要最接近 Antigravity 的节奏，同时仍保留明确的 Download / GitHub 入口。

### 5.2 下载页 `/download`

下载页从“平台卡片墙”改为“发布入口页”：

- 主区展示当前 release 判断、版本状态、来源与发布说明
- 辅区展示各平台下载入口
- 底部接已知发布节奏或注意事项
- 平台入口仍存在，但更像目录或发布条目，不像营销卡片

### 5.3 文档页 `/docs`

文档页改为编辑型文档结构：

- 左侧为固定窄导航
- 右侧为宽正文区
- 顶部为克制的大标题与摘要
- 文档索引页更像目录，不再做卡片宫格式产品页
- Markdown 正文继续保留，但周围框架改为深色 editorial 语言

### 5.4 更新日志页 `/changelog`

更新日志页改为更强的时间线 / 版本清单结构：

- 左侧可作为版本索引或时间线导引
- 右侧展示版本内容
- 版本之间主要靠线性节奏和空间断点区隔
- 这是最接近 Antigravity 表达的一页

### 5.5 路线图页 `/roadmap`

路线图页不再是三列卡片，而是公开计划书风格：

- 上部是方向判断与当前阶段说明
- 中部按“进行中 / 计划中 / 社区”分段
- 各段内部更像条目清单或宣言块，而不是孤立卡片

## 6. 导航与全站壳层

- 保留现有一级导航信息点不变
- 头部做得更弱、更像目录，而不是 SaaS 顶栏
- GitHub 与语言切换保留，但降低按钮感
- 页脚应与深色主基调统一，不再像浅色工具站收尾

## 7. 替换规则

### 7.1 删除或显著弱化的元素

- 大量圆角卡片容器
- 胶囊型按钮与标签泛滥
- 玻璃感、柔和浮层、浅色发光气泡
- 平均分布的模块网格
- 首页和内页各说各话的双重视觉体系

### 7.2 新规则

- 更少盒子，更多章节
- 更大标题，更短说明
- 更强左右分栏
- 更多分隔线，少整块包围边框
- CTA 更像动作入口，不像装饰胶囊
- 深色背景下通过局部浅面和排版对比做信息强调

## 8. 实施边界

### 8.1 保留不动的部分

- `/:locale/*` 路由结构
- locale 工具与切换逻辑
- release feed 与 fallback 数据层
- docs manifest 与 Markdown 内容
- 现有测试体系和页面职责边界

### 8.2 重点重构的部分

- `src/styles/tokens.css`
- `src/styles/global.css`
- `src/styles/layout.css`
- `src/components/layout/Header.tsx`
- `src/components/layout/Footer.tsx`
- 所有一级页面组件
- 首页相关 section 组件

### 8.3 预期结果

重构后官网仍然是同一个 GoNavi 官网，但用户第一眼感知将从：

`一个做得比较精致的工具站`

转成：

`一个更接近编辑型产品叙事、但仍然可用的深色官网`

## 9. 风险与控制

### 9.1 风险

- 过度靠近参考站，导致 GoNavi 产品信息变弱
- 首页风格转得太彻底，功能页可用性下降
- 只改视觉不改结构时，遗留组件层级可能产生样式冲突

### 9.2 控制策略

- 保留五个一级页面的信息职责不变
- 下载、文档、更新日志页优先保证可读性与可操作性
- 视觉重构以全站样式和页面骨架为主，不碰底层数据流
- 通过现有测试体系和新增页面断言兜住路由与关键行为

## 10. 验收标准

- 五个一级页面统一进入深色主基调
- 当前“气泡 / 胶囊 / 卡片站”观感明显消失
- 首页具备更强的长页面叙事与分栏结构
- 下载、文档、更新日志、路线图页和首页保持同一语言
- Download、Docs、Changelog、Roadmap 的可用性不因重构下降
- 现有测试通过，必要时补充视觉重构带来的页面行为测试
